# Daily routines, schedules and recovery

## Manual daily workflow

Read the registry/checkpoint, imminent deadlines, user changes and failed sync operations. Resolve meaningful pending operations after fresh reads. Find a small batch of official matches, rank them, prepare the highest-value requested drafts and provide the next three actions. Separate new findings, changed availability, preparation state and actual submissions.

Maintain the profile when the user sends new context; do not infer accomplishments from silence. Reuse good answers with source and version checks. Review current eligibility before employer entry, especially term and graduation windows.

## Optional scheduled workflow

Only set up after the user asks and agrees on cadence, time zone, scope and notification preference. Inspect existing schedules and update rather than duplicate. Use the scheduling tools actually available. A saved schedule is not proof of a completed unattended run; record last observed execution, completion and destination readbacks separately.

Suggested user-editable prompt: “At the agreed schedule, reconcile my private internship workspace from its registry and checkpoint, retry unresolved safe sync operations after fresh reads, research up to five matching official postings and draft internal next actions. Do not enter employer forms, upload, consent, submit, message anyone or start assessments. Save a checkpoint. Stay quiet on unchanged or nonactionable results; notify on a strong new match, deadline/availability change, failure or required decision.”

Recurring browser entry should not be assumed compatible with authentication and employer forms. Keep employer transmission supervised and scoped.

## Recovery

- **One destination failed:** preserve verified writes, fresh-read the failed destination and retry only its unresolved fields. Check for existing content to avoid duplicates.
- **Concurrent human edit:** compare before/current/proposed; retain human text and surface material conflict. Never force an old snapshot over a new revision.
- **Missing connection or sign-in:** record the exact user action; continue research/drafts. Never bypass policy or use extracted credentials.
- **Role no longer accessible:** mark blocked/unverified until evidence establishes closed; preserve history.
- **Changed resume/question:** invalidate affected review, retain prior artifacts, reverify the new version.
- **New chat/context loss:** read registry, current project instructions and latest checkpoint; fresh-read live records. Do not restart the interview or replay completed writes.
- **Missing dashboard capability:** keep a private document tracker working; record precisely which dashboard functions and data writes remain unavailable.

Always end a blocked run with current state, successful work, pending operations and an exact resume instruction. Never manufacture success receipts or mark partial setup complete.

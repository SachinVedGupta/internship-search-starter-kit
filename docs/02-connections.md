# Connections and capability verification

Check actual tools first; do not claim a plugin is installed because this document names it. Plans, organizational policies, platforms and rollouts vary. Verify current official product instructions in the user's account rather than guaranteeing a tier or interface label.

| Capability | Needed for | First verification |
| --- | --- | --- |
| Files + research | Interview, sources, drafting | Read supplied resume and open one official posting |
| Google Drive/Docs | Profile and tracker sync | Read an authorized document, make a small authorized private edit, read it back |
| Sites or private app hosting | Dashboard | Create owner-only workspace; test persistence and signed-out access denial before real data |
| Browser control | Employer form observation/entry | Open requested official role; distinguish read access from authorized entry |
| Local execution | Exact PDF checks and local packets | Confirm available files/runtime and inspect exact user-selected PDF |
| Gmail, optional | Submission and interview evidence | Read one narrowly scoped authorized application thread; never send |
| Calendar, optional | Interview/deadline planning | Read requested range; creating events requires scope from the user |
| GitHub, optional | Project evidence and private code | Read requested repositories; ownership alone does not prove contribution |
| Scheduler, optional | Requested periodic checks | Create only after scope agreed; inspect saved task and verify later execution separately |

Recommend Google Drive first. Gmail/calendar/GitHub are optional additions, not prerequisites to start. For unavailable connections, explain the exact user action in their current interface; complete independent work and record pending integration.

The user performs authentication, MFA and account consent. Never request credentials in chat or extract session cookies/tokens. Do not bypass a tool denial with an alternate hidden API.

A ChatGPT project groups sources/instructions; it does not automatically expose local folders. The built-in browser has a separate profile from the user's regular browser. For existing signed-in tabs use a supported browser extension where available. Do not assume Chrome or a custom draft guard is installed.

If using the kit in local Codex, download into a private workspace and keep personal files in `private/`. Save personalized project guidance in that private workspace's AGENTS.md, not this public template. Installing a skill or plugin is separate from adding a file as a project source. This kit does not automatically install either.

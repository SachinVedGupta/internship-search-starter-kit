# Resume library and career-profile maintenance

## Resume setup

Use the user's current resume and editable source. Do not import any author's career facts or resume blocks. Start with one general preset; add only useful role categories supported by the user's experience (for example general SWE, ML, infrastructure, finance or robotics). Their preferred format governs; for many US internships default to a readable one-page US Letter PDF unless the user has a different reasoned choice.

Read the current selected preset and supporting profile records. Reuse a suitable current version. For tailoring, create a company copy using supported complete sections; preserve approved wording, dates, metric qualifiers, links and formatting. Do not silently replace source-of-truth wording with an AI paraphrase. Retain prior versions and explicit user selection.

Save editable source and compiled PDF with matching versions and a useful name such as `Candidate_Resume_Company_Role_YYYY-MM-DD`. Do not overwrite originals. Verify actual file content, page size/count, links, legibility and rendered layout; bind review to exact PDF bytes/hash and role when file tools permit. A filename is not proof of content. If PDF inspection/compilation is unavailable, mark review pending rather than calling it verified.

Store private cloud files through supported storage and independently read back exact source/PDF pairing. Distinguish local saved file, dashboard attachment and employer attachment. Changing source invalidates old PDF pairing until rebuilt and reviewed; employer attachments do not auto-update. Preparing a variant does not authorize upload.

## Continuous profile intake

When the user asks to add an accomplishment, accept rough notes and existing sources without a required template. Read the existing related entry and career Doc section. Update the stable record; preserve milestones, evidence, previous versions and conflicts.

Capture problem/context, personal contribution, architecture, decisions/tradeoffs, debugging, results with conditions, lessons, maturity and next steps. Mark user-reported information with report date; event date is separate. Do not demand external proof for every user account, but do not call it independently verified.

Capture repositories, demos, captions and artifacts privately. Images prove only what is visible. A local attachment path or expiring link is not durable cloud storage. If no private media upload exists, save narrative and caption, mark media pending and state the missing step.

Write career changes to profile hub plus comprehensive profile Doc; reusable answers/letters/stories to relevant hub plus writing archive. Preserve detailed reusable context rather than collapsing everything into a resume bullet. Read back both destinations and checkpoint pending work. Never infer that unrelated chats or global memory automatically synchronize new facts.

# Discovery, drafts and employer entry

## Discovery

Read current search preferences, full known history, exclusions and pending sync. Use job boards and internship repositories as leads; official postings establish facts. Verify official URL/requisition/title, internship term, location, student/graduation/return-to-school rules, work authorization, deadline and current availability. An access error is blocked/unverified, not closed. Do not invent posting dates; retain earliest found-on date.

Rank Priority / Strong / Selective / Skip by role fit, learning, team/product, likelihood, timing and preparation effort. Explain meaningful tradeoffs. Start with three roles; choose later batch size with the user. Check employer/affiliate limits and active overlapping processes. Update dashboard and tracker from one reconciled change set and read back both.

## Preparation

Read the relevant full profile and actual official posting. Observe accessible application prompts including required flags, choices, conditionals and character limits; record source/read date and coverage gaps. Do not claim a complete form inventory from a landing page. If observation requires login/account creation, let the user handle it and continue supported internal drafting.

Draft all supportable substantive answers in the user's voice. Use concrete personal contributions and evidence; distinguish motivation/inference from biography. Do not invent product usage, relationships, credentials or impact. Unknown routine factual choices remain unknown unless the user has explicitly chosen an inference policy. Never transplant another person's LinkedIn/event fallback or citizenship.

Mark each question drafted/needs review, user-approved, missing fact, inaccessible or not applicable with reason. Material prompt/choice/fact/answer changes invalidate affected approval. Preserve user edits and earlier answer versions. Keep the polished answer separate from grounding notes. Prepare a resume using `docs/06-resumes-and-profile.md`.

## Optional authorized employer entry

Before external entry, record employer/domain, scope and authorized personal fields; get a separate upload authorization if needed. User instructions naming particular applications can supply scope; do not ask repeatedly when already clear. Internal setup permission is not employer-entry permission.

Use supported connectors or supervised browser interaction. If Simplify is available and chosen, inspect its settings and prevent unrequested resume attachment before using autofill. Verify every populated field against current facts and preserve manual edits. Handle supported complex and conditional fields as well as contact autofill. Record exact entered fields, omissions and blockers without logging sensitive values unnecessarily.

Advance through accessible intermediate pages including experience and questions through review. Inspect the behavior of every Next/Continue/Finish control; stop before any control that submits/finalizes. Never bypass required fields by inventing information. Consent/signature actions require their own scope and exact wording review; default to user handling. Credentials, MFA, account creation, assessments and final submission stay with the user.

No custom Draft Guard is included. If one is separately installed, verify protection on the exact tab, re-arm after navigation/reload/extension changes as required, and treat it as defense in depth rather than a guarantee. Do not promise protection from instructions alone.

Separately verify employer draft saving when visible; populated fields do not prove autosave. Record attachment readback for the exact uploaded resume. A local file hash or upload click does not prove attachment. Stop browser interaction before the user reviews and submits. Report review-ready only for observed completed scope; otherwise give exact gaps.

## After the user submits

Use visible portal confirmation or explicitly authorized relevant confirmation email/user report, labelled by source. Record exact role and supported date; distinguish a self-report from independently seen confirmation. Reconcile Applied and submission evidence across both trackers with separate readbacks. Never mark Applied merely from a draft or attempted submit.
